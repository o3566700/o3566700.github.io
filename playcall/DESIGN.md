# PLAYCALL 戰術板 — 設計文件 v0.1

手機直式、網頁、房號連線的 **5v5 全場籃球即時戰術對戰**。
玩家不操控球員，而是「指定球員 → 下動作 / 戰術」，其餘交給 AI。
勝負來自時機、資源管理與讀對手，不是手速。

---

## 1. 已定案決策

| 項目 | 決定 |
|---|---|
| 類型 | 戰術板即時對戰（類皇室戰爭的出牌節奏） |
| 人數 | 全場 5v5，每隊只有先發 5 人，**無替補** |
| 比賽長度 | 4 節 × 每節 1 分鐘，進攻時限 8 秒，一場約 5 分鐘 |
| 操作 | 只能「點球員卡 → 選動作/戰術 →（必要時）點目標」 |
| 資源 | 體力（球員・整場）＋ CD（球員・數秒）＋ 戰術點（全隊） |
| 犯規 | 第二版再做 |
| 首發隊伍 | 紐約尼克 vs 聖安東尼奧馬刺（2026 總冠軍賽重演） |

## 2. 操作流程

```
畫面底部固定 5 張球員卡（點陣頭像 / 體力條 / CD 轉圈）
① 點球員卡 → ② 彈出動作（3–4 個，依攻守自動切換）→ ③ 需要目標時點場上球員
```

- 未被指定的球員由 AI 依位置自動跑位、補防、搶籃板（「普通」水準）。
- 指令會在數秒內接管相關球員，執行完畢交還 AI。

### 「不能連用」規則
1. 同一名球員 **不能連續兩次** 被指定，中間必須先指定過其他人。
2. 且該球員 CD 必須轉完。

## 3. 資源系統

### 3.1 戰術點（全隊）
- 上限 3 點，開場 1 點。
- 每次攻守交換 +1；守下一球（抄截、蓋帽、對方未進）再 +1。
- **單人動作不花戰術點**；**團隊戰術** 花 1–2 點，參與球員全部進 CD。

### 3.2 CD（球員）
- 單人動作 6–10 秒，招牌技 15 秒，團隊戰術參與者 8 秒。
- 疲勞時 CD 延長（見 3.3）。

### 3.3 體力（球員，整場共用）
上限 100，整場 4 節共用，沒有替補，是最重要的長期資源。

**消耗**
| 來源 | 數值（初版，待調） |
|---|---|
| 被指定：一般動作 | -6 ～ -10 |
| 被指定：招牌技 | -15 |
| 團隊戰術參與 | -5 |
| 碰撞（掩護、背框、切入撞人、卡位） | -1 ～ -5，依雙方 **強度** 差距 |

碰撞也包含 AI 自動發生的接觸，因此可以刻意「消耗對手球星」。

**回復**
| 來源 | 數值 |
|---|---|
| 未被指定且無碰撞 | +0.5 / 秒 |
| 節間休息 | +20 |
| 暫停（每場 2 次） | 全隊 +15，並重置所有 CD |

**分段效果**
| 體力 | 狀態 | 效果 |
|---|---|---|
| 100–60 | 正常 | — |
| 59–30 | 疲勞（黃） | 速度 / 命中 / 防守範圍 -10%，CD +25% |
| 29–1 | 力竭（紅） | 能力 -25%，CD +50%，招牌技鎖住 |
| 0 | 抽筋 | 無法被指定，AI 以 60% 水準打 |

## 4. 球員與動作

### 4.1 能力值
`三分 3PT / 中距離 MID / 切入 DRV / 傳球 PAS / 防守 DEF / 籃板 REB / 速度 SPD / 身高 HGT / 強度 STR`（0–99）

### 4.2 每名球員 = 2 位置動作 + 1 招牌技 + 1 被動

| 位置 | 進攻動作 | 防守動作 |
|---|---|---|
| 後衛 | 單打切入、急停跳投 | 貼身（目標）、抄截賭博 |
| 側翼 | 空切、接球三分 | 貼身（目標）、協防 |
| 長人 | 背框要位（目標）、掩護（目標） | 護框、卡位籃板 |

## 5. 技術架構

```
┌──────────── 手機瀏覽器 ────────────┐
│  UI 層   大廳/房號、選隊、球員卡、HUD │
│  繪圖層  Canvas 點陣圖、動畫、特效    │
│     ▲ 每幀讀取狀態（唯讀）            │
│  模擬核心 sim/  純邏輯，不碰 DOM/網路 │
│     ▲ 指令            ▼ 快照          │
│  網路層  主機 / 客戶端                │
└──────────────┬─────────────────────┘
               │ WebRTC (PeerJS) 房號配對
        對手手機（同一套程式）
```

### 5.1 模擬核心 `sim/`
- 純函式：`step(state, commands) → state`，固定 20 tick/秒，與畫面幀率分離。
- 子系統：比賽流程（跳球、進攻、死球、換邊、節/時間/進攻時限）、球員 AI、指令/戰術劇本、判定（投籃、傳球、抄截、蓋帽、籃板、碰撞）、資源（體力、CD、戰術點）。
- 可直接用於：主機端、未來的伺服器、單機 AI 對手、自動化測試。
- 亂數使用可設定種子的 RNG，方便重播與除錯。

### 5.2 連線
- **第一版：主機權威**。開房者跑模擬，10 Hz 送快照；客戶端只送指令並做內插。
- 第二版：模擬搬到 Cloudflare Durable Objects（天梯、防作弊），只換網路層。
- 風險：部分行動網路 NAT 無法建立 WebRTC，若測試遇到，提早改用 WebSocket 中繼。

**協定**
```
客戶端→主機  {type:"cmd", player, action, target, tick}
主機→客戶端  {type:"snap", tick, players[10], ball, score, clock, stamina[10], cd[10], tp[2]}
主機→客戶端  {type:"evt", kind:"shot|make|steal|block|collide", ...}
```

### 5.3 繪圖：HD-2D（參考《歧路旅人 II》）
- **場景**：three.js 斜上方透視鏡頭的 3D 球場；光暈（bloom）、移軸景深、場館打光、陰影、粒子特效。
- **鏡頭**：預設只拍進攻方的半場（陣地戰 10 人都在同一半場），攻守轉換時平滑移到另一邊；球員在手機上約 5 公分高。
- **場上角色**：約 3 頭身的點陣逐格動畫，以面向鏡頭的看板（billboard）放進 3D 場景，最近鄰取樣保持點陣清晰。
  - 每人 2 張 6×6 sprite sheet：正面（朝右下）、背面（朝右上），往左時水平翻轉。
  - 動作：待機、跑、運球、投籃、防守、傳球，各 6 格。
- **精細立繪**：愛馬仕產的精細全身圖與頭像，用在球員卡、招牌技特寫（約 1 秒）、開場陣容與得分慶祝。
- 美術來源：愛馬仕用 Gemini 產圖 → Drive → 我負責去背、格線校正、裁切與打包。

### 5.4 資料
- `data/teams.json`：隊伍代碼、配色、5 名先發與能力值、招牌技、被動。
- `data/actions.json`：動作與戰術的消耗、CD、持續時間、劇本參數。
- `data/names.json`：真名 ↔ 虛構名對照，公開版一鍵切換（NBA 隊名/球員姓名肖像授權考量）。

## 6. 開發里程碑

1. **M1 模擬核心（無畫面）**：比賽流程、AI 跑位、投籃判定、體力/CD/戰術點；用文字 log 跑完整場。
2. **M2 單機可玩**：Canvas 點陣圖、球員卡 UI、對電腦 AI。
3. **M3 連線**：PeerJS 房號、主機權威快照同步。
4. **M4 平衡**：數值調整、手機實測。
5. **第二版**：犯規/罰球/犯滿、伺服器權威、天梯、更多隊伍。
